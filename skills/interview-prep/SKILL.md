# 面试准备技能

面向技术岗的面试准备流程。核心判断：**面试考的不是「你知不知道」，而是「你能不能把
做过的事讲清楚、把没做过的事说诚实」**。所以这个技能的重点是组织答案结构，而不是
堆知识点。

## 能力

- 设计可追问三层的项目介绍（STAR-C 的面试版）
- 打磨自我介绍（1 分钟 / 3 分钟两个版本）
- 按岗位与轮次排出复习优先级，而不是均匀用力
- 生成模拟追问，暴露「答不上来但简历里写了」的风险点
- 准备反问环节的问题清单

## 核心流程

1. **摸清面试形态**：公司 + 岗位 + 轮次（一面技术 / 二面项目 / HR）。不同轮次
   考的东西完全不同，不确认就准备等于白准备。
2. **项目经历过三遍**：
   - 第一遍（30 秒版）：项目是什么、你的角色、最亮的一个结果
   - 第二遍（3 分钟版）：背景约束 → 技术选型对比 → 你做的关键决策 → 结果与代价
   - 第三遍（追问版）：每个技术选型都准备「为什么不用 X」——**这一层是分水岭**
3. **算法题**：按目标公司题型准备，重在做题节奏而非刷题量：
   说思路 → 举例验证 → 写代码 → 主动跑一个边界用例 → 复杂度分析。
   卡壳时的正确动作是说出来（「我先想想暴力解」），沉默是最大的失分项。
4. **反问环节**：准备 3 个具体问题（团队在做什么、这个岗位的挑战、对我的期待），
   不问官网能查到的信息，不问薪资（留给 HR 轮）。

## 高频追问清单（项目深挖）

面试官问「还有什么想问的」之前，通常会沿这几条线挖：

- 这个方案的另一条路是什么？为什么没选？（考察技术判断）
- 上线后出过什么问题？怎么定位的？（考察真实参与度）
- 如果流量涨 10 倍，哪里先崩？（考察系统理解）
- 这套东西是你独立做的吗？哪部分最难？（考察诚实度与深度）
- 你从这个项目里学到什么？（考察反思能力）

**答不上来的正确处理**：说清「我知道的边界在哪里 + 我会怎么去查证」。
编造的技术细节在第二轮追问必穿，且会连带毁掉其他真实经历的可信度。

## 输出格式

准备计划按「**必须准备 / 建议准备 / 可放弃**」三档给，并标出每项的预期投入时间。
模拟追问时一次给 3 个问题，等用户回答后再给下一批——一次抛 20 个问题没法练。

## 示例

用户：明天要面一个后端岗，帮我准备一下
助手：[触发 interview-prep 技能] 先确认：什么公司、几面、面试官是技术还是 HR？
然后按轮次给准备清单，从项目三遍讲法开始。
