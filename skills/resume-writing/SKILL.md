# 简历写作技能

面向技术岗（后端 / 算法 / 大模型 / 数据）求职者的简历打磨流程。核心原则：**简历不是
自传，是一份针对目标岗位的证据清单**——每一条都要能被面试官追问三层而不塌。

## 能力

- 分析现有简历，逐条指出问题（弱动词、无量化、职责罗列、技术栈堆砌）
- 根据目标岗位 JD 重写项目经历，补齐量化结果与技术取舍
- 检查简历的结构与篇幅（应届一页，社招两页以内）
- 给出可执行的修改清单（按优先级排序，不是泛泛而谈）

## 核心流程

1. **先问三件事**（缺一件就先问，别猜）：目标岗位与级别、当前简历（或项目清单）、
   投递时间线。没有目标岗位就无法判断什么该突出。
2. **逐条审阅项目经历**，用 STAR-C 检查每条 bullet：
   - **S/T** 场景与目标：一句话说清在什么约束下做什么
   - **A** 动作：你**自己**做了什么技术决策，为什么这么选（有没有对比方案）
   - **R** 结果：量化指标（延迟、QPS、准确率、成本、覆盖规模），没有数字就写
     相对变化（「较原方案降低约 40%」）
   - **C** 代价与边界：这套方案的短板是什么。**面试深挖的入口就在这里**，
     简历里留一句诚实的技术边界，比藏着被问穿强得多
3. **动词替换**：负责 → 设计/实现/重构/优化/推动；参与 → 独立完成/主导 X 模块
4. **技术栈按岗位排序**：JD 里出现且你真用过的放前面；只是「了解」的不要写进
   项目经历，放进技能栏并诚实标注熟练度

## 常见问题（审阅时按此清单逐条过）

| 问题 | 表现 | 修法 |
|---|---|---|
| 职责罗列 | 「负责后端开发」 | 换成「实现 X 接口，P99 从 800ms 降到 120ms」 |
| 无量化 | 「提升了系统性能」 | 补数字或相对变化；实在没有就写规模（「日均 20 万次调用」） |
| 技术堆砌 | 一行列 20 个技术名词 | 每个技术名词都要能对应一段经历，否则删掉 |
| 团队功劳 | 「我们完成了…」 | 改成「我负责 A 模块，与 B 同学联调 C 接口」——面试官只关心**你**做了什么 |
| 时间断档无解释 | 空窗期没有交代 | 不用写进简历，但要准备好一句话解释 |

## 输出格式

审阅结论按「**必须先改 / 建议改 / 可选**」三档给，每条都带上原文片段与改写示例。
一次给太多建议等于没给，先解决会直接被筛掉的硬伤（无量化、职责罗列、篇幅超长）。

## 示例

用户：帮我看看这份简历有什么问题
助手：[触发 resume-writing 技能] 我先确认两件事：你投的是哪个方向、什么级别？……
然后按 STAR-C 逐条过，先给必须改的几条。
