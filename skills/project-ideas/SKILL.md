# 项目创意技能

从用户**已有的笔记与经历**里长出项目，而不是推荐一份网上的「10 个必做项目」清单。
核心判断：项目本身没有价值，**「你在这个项目里做了什么技术决策」才有价值**——
所以选题的第一标准是「能不能产生一个值得在面试里讲三分钟的取舍」。

## 能力

- 从用户的知识库里找「学过但没用过」的点，配成可落地的小项目
- 判断一个点子值不值得做（有没有技术取舍、能不能量化、工期是否可控）
- 给每个点子定最小可交付版本（MVV）与可量化的验收指标
- 指出这个点子面试时会被追问什么

## 核心流程

1. **先摸清用户手里有什么**：用 `search_knowledge` 检索用户最近的学习主题，
   选题要贴着已有知识——用完全没接触过的技术做项目，八成停在环境搭建那一步。
2. **每个点子写清四件事**（缺一件就不给）：
   - **要解决的问题**：谁在什么时候会用到（自己也算，但要具体）
   - **必须做的技术取舍**：至少一处「A 与 B 为什么选 A」的决策点。
     没有取舍的项目（一个 CRUD 后台）在简历里写不出东西
   - **最小可交付版本**：多久能跑起来，砍掉什么
   - **验收指标**：可量化的数字（延迟、准确率、成本、覆盖的真实数据规模）
3. **按「做完能拿到什么」排序**，不按「技术新不新」排序。
   一个做完的普通项目，胜过一个停在半路的新潮项目。
4. **明确不做清单**：每个点子都要写清楚先不做什么（登录注册、多租户、移动端），
   这是项目不烂尾的关键。

## 好点子与坏点子的判据

| 信号 | 好点子 | 坏点子 |
|---|---|---|
| 技术取舍 | 有明确的对比方案与选型理由 | 只有唯一实现路径 |
| 数据来源 | 有真实数据（自己的笔记、公开数据集、自己的使用记录） | 全靠编造的假数据 |
| 结局面 | 指标能持续观察（跑一次就有数） | 做完了「感觉挺好」 |
| 工期 | 2-4 周能出第一版可演示的东西 | 需要 3 个月才有东西给人看 |
| 面试价值 | 面试官能追问三层 | 追问一层就问到底了 |

## 输出格式

一次给 3 个点子（不要更多，用户会挑花眼），每个点子按上面四件事写，附一句
「面试会被追问什么」。最后给一个明确的推荐排序与理由。

## 示例

用户：我想做个项目放简历里，做什么好？
助手：[触发 project-ideas 技能] 我先查一下你最近在学什么、笔记里有哪些主题……
然后给 3 个贴着你现有知识的点子，每个都带技术取舍与验收指标。
