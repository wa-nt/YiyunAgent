# 简历 Bullet —— 第二大脑 Agent

> 使用说明：每条 bullet = 技术动作 + 量化结果 + 业务价值。数字均来自代码库实测
> （测试数、commit 数、模块行数可复核）；评测数字的口径与局限见每条备注，
> 面试被追问时按备注回答，不要把点估计说成显著结论。

## 一句话版本（放简历项目名后）

**第二大脑 Agent** —— 个人知识管理 Agent：分层记忆 × 上下文治理 × Skill 化 × 评测与可观测（Python / FastAPI / SQLite+sqlite-vec / 双协议 LLM 接入）

## 推荐 Bullets

- 独立设计并实现个人知识管理 Agent 全链路：文档采集（文件/URL/PDF → 分块 → embedding）→ 混合检索 → ReAct Agent 运行时 → SSE 流式前端，共 30+ commits、3300+ 行实现代码、324 条自动化测试全绿

- 实现三路混合检索（sqlite-vec 向量 + BM25 + 实体匹配，RRF 融合），检索模式可配置切换（hybrid/vector/bm25），为消融实验提供单因素对照基线

- 设计分层记忆系统：LLM 从对话抽取候选记忆 → 重要性评分 → 归一化文本去重（含数字一致性、否定词极性守卫）→ LLM 冲突检测（不覆盖旧记忆，标 conflict 并衰减置信度）；落库前过滤 API key/密码等敏感信息，防止每轮回灌 system 提示

- 实现上下文治理三策略（工具结果清理 / 历史压缩 / token 预算），独立可开关；修复了"占位符反而放大 prompt""截断后超预算"等边界问题，治理只改 prompt view 不改原始数据

- 实现 Skill 系统（渐进式披露）：SKILL.md 声明触发词与能力，命中后按需注入提示词并注册专用工具；内置 5 个技能，含简历体检与 JD 关键词缺口分析工具

- 建立可观测体系：LLM/工具/skill 调用全量埋点（fire-and-forget 不阻塞主流程），按 provider 定价表估算成本，提供成本看板 API（过滤/分页/聚合）

- 构建评测框架与 38 条中文评测集（按 LoCoMo 分类：single-hop/multi-hop/temporal/跨会话偏好/对抗/长会话），实现 8 组消融矩阵（记忆×压缩×检索）验证各模块贡献，结果含 git commit 与配置快照可复现

- 工程纪律：每个模块经过"实现 → 独立审查 → 修复 → 复审"循环，累计修复 5 个 critical 级缺陷（记忆静默丢失、敏感信息泄漏、成本单位错误 1000 倍、评测异常泄漏真实 API、非 UTF-8 文件炸掉服务），全部有变异测试守护

## 面试问答备忘（数字的口径）

- **"324 条测试"**：`python -m pytest tests/ -q` 实测。含大量变异测试（故意改回错误实现验证测试能抓住），不是凑数
- **"评测集 38 条"**：brief 原目标 150-300 条，无真实 API key 无法跑真实评测，故先建框架 + 高质量小规模集合；框架支持任意规模。分类比例严格对齐 LoCoMo
- **消融数字**：本仓库未附真实 LLM 的消融结果（无 key）。面试时说"框架与评测集已就绪，消融矩阵可一键跑出"，比编数字安全
- **token 成本**：成本看板的 token 数来自 provider 返回的 usage（真实）；上下文治理的 token 预算是字符估算（中文偏乐观 3-4 倍），两者口径不同，别混用
- **"修复 5 个 critical"**：指开发过程中由独立审查代理发现、并经验证修复的缺陷，不是线上事故

## 被问"为什么不用 XX"时的回答

- **为什么 SQLite 不用 PostgreSQL**：本地优先、零依赖部署；数据量在个人量级内 PG 无收益，存储层是薄适配层，真到需要时可迁移
- **为什么不用 LangGraph**：设计初期列入依赖，实现时发现手写 ReAct 循环（≤6 轮工具调用）足够且更透明可控，就没引入重型编排框架
- **为什么记忆去重用文本相似度不用 embedding**：memories 表未加 embedding 列，归一化文本相似度 + 数字/否定词守卫在当前量级足够；评测若显示污染率偏高，加列切 cosine 是一步之遥
